# Authentication and account boundaries

Read before changing auth handlers, sessions, ownership or account navigation.

## Data and account boundaries

Better Auth owns the `user`, `account`, `session`, and `verification` collections. The MongoDB user ID is the stable application identity; the provider/account pair identifies the Google login. Profile data is limited to the provider's standard name, email, verification status, and optional image, plus authentication timestamps. Sessions expire after seven days and refresh after one day of activity. Google token material is encrypted at rest using the authentication secret; it is not returned by `/api/account`. The authentication collections contain no application roles, analytics, or learning progress. Account confirmation records, subsection preferences, and reset generations are stored separately in `studyState`; see [Learning progress](../learning-progress.md).

Only Google sign-in is enabled. Password authentication and account linking are disabled. HTTPS origins use Secure, HttpOnly, host-only cookies; localhost uses HttpOnly cookies over HTTP. Cookie session caching is disabled so a revoked/expired session is checked against the database. Better Auth handles OAuth state, origin/CSRF checks, session revocation, and its default rate limiting. The default rate limiter is process-local; it is not a distributed abuse-control system.

Every new Google sign-in requests `prompt=select_account` so users can choose a different identity even when the browser or standalone PWA retains a Google session. Signing out of Mosaic revokes its current application session; it does not sign the user out of Google. Existing valid Mosaic sessions remain signed in across revisits. The owner confirmed account selection and switching in the installed development PWA on October 15, 2026; an authorization URL check alone does not establish device behavior.

The account and legacy sign-in routes share `AccountScreen` and `AccountSession` presentation. Profile avatars use initials derived from the existing name; no additional profile fields or remote avatar requests are introduced. Sign-out sits to the right of the wrapping name/email block; no provider-status row is displayed. The Google button uses the locally stored official [Google G asset](https://developers.google.com/static/identity/images/g-logo.png) linked by Google's [branding guidelines](https://developers.google.com/identity/branding-guidelines). Decorative mosaic artwork uses inline SVG and CSS gradients; the account page remains scrollable on short screens and with long profile data. See [Account and learning presentation](../account-presentation.md) for layout and accessibility constraints.

Use `requireUser(request.headers)` from `src/lib/auth/server.ts` for future account-owned handlers. Derive document ownership from the returned `user.id`, never a body/query parameter. `/api/account` demonstrates this boundary: authenticated requests receive only ID/name/email; guests receive `401`, untrusted configured hosts `403`, and unavailable configuration/database `503`, always without caching.

Learning navigation uses separate in-memory guest/account sessions, with no automatic guest-to-account import. Durable progress/preferences remain owner-namespaced. See [Study sessions](../study-sessions.md) for runtime and reload behavior. The permanent `/account` page shares the `(study)` layout with `/`, `/learning`, and `/review`; parentheses organize files and do not appear in public URLs. Client-side visits and returns retain independent mounted study/review feeds, including order, active card, informational page, quiz choice, and flip side. Inactive feeds are hidden, inert, and have global keyboard/mousewheel input disabled. Focus moves to the destination heading, restores the originating profile entry on return from My learning/review, or moves to the study/review return control as appropriate. The legacy `/sign-in` route remains independently available and sits outside that layout. A full reload or external Google OAuth round trip verifies identity and generates a fresh feed from its saved progress/preferences. Signing out revokes the current server session; it does not revoke other devices' sessions. Session and progress stores are namespaced by guest/account identity and remount on sign-out or account switching; the previous account state is removed from the displayed context. Its pending outbox remains isolated for a later return by the same account. Understanding confirmations and selected subsection IDs synchronize through `/api/study-state`. Guest progress remains separate, without a transfer action. Study and review navigation state remain in memory for the open runtime.
