# Account and learning presentation

The owner-approved dark Mosaic direction uses a graphite base (`#171c2b`), raised slate surfaces, lilac (`#b7a0ff`), cyan (`#85deed`), and small apricot highlights. Account presentation styles are local to `account-screen.module.scss`; they do not introduce a theme framework or change the learning-feed palettes.

## Graphics and layout

`MosaicArtwork.tsx` supplies inline SVG tiles, destination illustrations, and action icons. The shared brand mark comes from `public/icons/mosaic-mark.svg`, used directly inside the application and as the SVG favicon. Run `npm run generate:icons` to regenerate the ICO favicon and the 180/192/512px PNG app icons from this source. The generated app SVG/PNGs add a graphite background and mask-safe padding; both production and development manifests share them. Metadata also declares the 180px Apple Touch Icon. Installed PWA/home-screen icons may remain cached by the OS until it refreshes or the owner reinstalls the shortcut. Tile gradients use per-instance `useId` identifiers. Graphics are decorative (`aria-hidden`, `focusable="false"`, `pointer-events: none`), use no raster backgrounds, SVG filters, remote assets, or decorative background animation. The existing official local Google G image remains on the branded sign-in button. PNG/ICO exports are limited to platform app icons; UI artwork remains vector-based. No dependencies are added. Small/landscape layouts reduce background artwork; forced-colors mode removes the background compositions and retains semantic controls.

The profile presents an initials avatar and a name/email identity block. Sign-out is a separate button to the right, aligned with the first name line. The name column can wrap long words while sign-out retains its touch target. No provider-status row is displayed. Profile destinations remain My learning and Review; review counts derive from the existing selected-section review session. Guest progress remains separate, with an explicit note.

The legacy sign-in route uses "Мой аккаунт" while resolving or displaying an account. The shared top navigation always places one parent link at the left and the Mosaic brand at the right. My learning returns to Profile; Profile and the legacy sign-in page return to the feed ("К карточкам"). No second back link or duplicate continue-learning/guest-feed link is shown. Account-check status sits below the decorative tile area without an opaque surface, border, or placeholder square. Error recovery keeps its readable surface and retry action. Summary artwork is clipped at the rounded summary boundary, not at the smaller SVG viewport, so interior tiles keep their complete contours.

Signed-out screens rely on the Google sign-in button's label without a duplicate explanatory sentence over the background tiles. Profile destination cards, sign-in/error panels, chapter accordions, the overall progress summary, the standalone shuffle action, and reset dialogs share one glass-surface mixin: translucent slate fill, a light border, and a static 10px backdrop blur (including the Safari-prefixed property). Nested retry/confirmation controls use the same translucent palette without stacking additional blur layers. Navigation, disclosure, sign-out, and scoped reset actions remain text/icon controls; destructive confirmation retains its rose treatment. The Google button itself retains its opaque branded surface and text contrast. Unsupported blur falls back to the same translucent fill; forced-colors mode removes blur and uses a system background. No page-wide or animated blur is introduced, and the modal backdrop continues to dim the page behind confirmation dialogs. Summary tiles remain inside the summary clipping container; backdrop blur does not blur the summary content itself.

My learning shows an overall progress summary, then independent chapter accordions and indented subsections. Full registry titles, chapter/subsection membership, separate selection/disclosure actions, and chapter aggregate values are preserved. Overall, chapter, and subsection resets remain distinct visible actions with the existing scoped confirmation dialog. The first subsection's cyan accent uses an explicit `data-section="fe-1.1"` presentation rule; other groups retain the default lilac accent. Colors do not determine membership or progress.

Percentages and completed counts remain data-derived. Native progress elements expose values immediately; this increment adds no animation or new award behavior. Reset, selection, synchronization, auth, and shuffle semantics remain as described in [Learning progress](learning-progress.md), [Study sessions](study-sessions.md), and [Authentication](authentication.md). The existing Google sign-in route shares the same presentation primitives and keeps the existing Google button branding, recovery states, and callback behavior.

## Accessibility and review

Keep the 44 CSS pixel minimum targets, visible cyan focus outlines, native checkbox partial states, disclosure `aria-expanded`/`aria-controls`, hidden-panel tab exclusion, and reset-dialog focus restoration. Main screens remain fixed safe-area-aware scroll containers, including in landscape; artwork cannot create horizontal scrolling or obscure text. Background fills and SVG gradients need no motion alternative because they are static.

Contrast checks must cover foreground/background pairs and adjacent progress/focus colors, including hover surfaces, rather than inspecting palette swatches alone. Disabled controls and decorative dividers do not establish contrast for active controls. A spot audit is not a claim of full WCAG conformance; record measurements and the browser/device scope with the task's validation evidence.

Glass surfaces require checks against the composited backdrop rather than the old opaque slate swatches. Keep secondary text over quiet dark regions; decorative tiles must not run behind text. Fixed pairs remain lilac/cyan progress fills against their track (3.57:1 / 5.14:1). Large white initials against the lightest avatar gradient stop have 3.57:1 contrast. Keep text away from the brighter decorative tile fills; palette ratios alone do not validate text overlapping artwork. Physical iPhone/PWA validation and exhaustive browser/state coverage are separate from these color calculations.

Illustrated empty states and an alternative feed-card progress placement require separate visual proposals. This presentation increment does not select Lottie, change feed actions, or move progress on a learning card.

## Loading states

The owner approved the Mosaic tile loader after reducing its travel and scale change. `MosaicLoader` is a presentation-only component shared by initial feed/review loading, account checks, and the prominent overall progress summary. Its four CSS tiles assemble in a 2.8-second cycle, with 0.1-second staggered starts. Maximum per-axis travel is 5px for the 74px hero mark and 2px for the 30px inline mark; scale stays between 0.96 and 1, opacity between 0.8 and 1. The mark is decorative; one stable `role="status"` label describes the operation without announcing animation frames.

Only initial blocking states use the loader. Existing cards and progress remain visible during background synchronization, whose existing text status is retained. Chapter/subsection summaries and profile destinations keep plain loading labels rather than adding many concurrent animations. The account-check loader keeps a transparent background below the artwork. The feed loading view uses the approved graphite palette and retains the Profile escape link; review loading identifies review explicitly.

No artificial minimum display time, new fetch, timer, data gating, or progress percentage is introduced. Existing ready/error/empty conditions still replace the loader immediately; existing retry/sign-in/sync recovery remains available. This presentation change does not fix or mask the separately tracked intermittent bootstrap issue (MOS-36). Reduced-motion uses a fully assembled, static mark. Inactive mounted feeds receive `animate={false}`; forced-colors mode shows the text without decorative tiles. CSS animates only tile transform and opacity; the moving tiles need no image requests. The feed header reuses the canonical SVG brand image. No Lottie runtime, SVG filters, or dependencies are added for loading. The overall-summary loading label reserves space for its decorative artwork, including at 320px.
